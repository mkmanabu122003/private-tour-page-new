## 1. ビルド方式（最重要）

このリポジトリは **Astro ではない**。`astro.config` は存在しない。実体は **Vite 5 + React 18 + react-router-dom 6** で、ビルド時に SSR プリレンダーして静的 HTML を `dist/` に書き出す構成。

| 項目 | 実態 |
|---|---|
| フレームワーク | Vite (`vite.config.ts`) + React 18 + SWC |
| Adapter | なし（Astro / Next adapter なし）。ホスティングは Netlify 静的 (`publish = "dist"`) |
| `output` 相当 | 静的サイト。`package.json` の `build` がクライアントビルド → SSR バンドル → `prerender.mjs` |
| ランタイム SSR | なし。Netlify Functions はフォーム送信後のメール／Slack のみ |
| SPA fallback | **廃止済み**。`netlify.toml` の catch-all は `/*` → `/404.html` status 404 |

ビルドコマンド:

```
vite build && vite build --ssr src/entry-server.tsx --outDir dist/server && node prerender.mjs && rm -rf dist/server
```

`prerender.mjs` は `AppRoutes.tsx` のリテラル `path="..."` と `TourDetail.tsx` の `tourSchemaData` キーからルートを導出し、各 URL を `renderToString` して `dist{url}/index.html` に書き込む。ブログ記事を含む **全 166 ルートが静的 HTML として dist に出力される**。空の SPA シェルだけを出すルートは、このパイプラインが成功する限り存在しない。

### クライアント側でのみ描画されるもの

独立した「SPA 専用ページ」（プリレンダーされない URL）は **ない**。ただし次はハイドレーション後に初めて見える。

| 対象 | 理由 |
|---|---|
| `StickyBookingBar` | `scrollY > 300` で表示。初期 HTML では画面外 |
| お問い合わせ成功 | 別 URL へ遷移せず toast。サンクスページなし |
| Diagnostic クイズの設問・結果 | トリガーカードは HTML に出る。設問〜結果画面は `useState` |
| ツアー詳細のカルーセル操作 | Embla。最初の画像はプリレンダーされる |

`index.html` の `<html lang="en">` はプリレンダーで書き換えない。スペイン語ページも HTML 言語属性は `en` のまま。`SEO.tsx` は `htmlAttributes` を設定しない。

Netlify: `pretty_urls = false`。末尾スラッシュは `netlify/edge-functions/trailing-slash.ts` が 301 で除去する想定（`config.path = "/*"`。`netlify.toml` に `[[edge_functions]]` の明示登録はない。Netlify のディレクトリ規約に依存）。

2. ブロッカー: アフィリエイト ID / 開示コンポーネント / outbound イベントがゼロ。導入 PR の前にプログラム選定と env 名が要る。  
3. ブロッカー: ES sticky が英語 `/contact`、Food/Night の ES URL が 301、Hakone メール料金がサイトと不一致。成約より先に漏れている。  
4. ブロッカー: Supabase が無い。予約 CRM を Supabase にするなら別設計。今の問い合わせは Netlify Forms + Resend だけ。  
5. 推奨 Phase 1（成約）: sticky の言語、Hakone メール料金、Food/Night 料金の一本化、Imperial/Yanaka FAQ、フッター死リンク。ツアーページの URL は変えない。  
6. 推奨 Phase 2（ブログ→ツアー）: Nikko vs solo 型で CTA を先に置き、hreflang 欠落を埋め、ES 重複の扱いだけ Open questions で決める。  
7. 推奨 Phase 3（補助収益）: JR Pass 記事の公式・SmartEX を「ここで予約できる」紹介リンクにし、開示コンポーネントを全該当ページへ。他社ツアー URL は置かない。  
8. 推奨 Phase 4: outbound クリック計測、sitemap をルートから生成、ES `lang`、サンクス URL の要否。  
9. 各 Phase は 1 PR = 1 テーマ。この監査 PR はマージしない。  
10. 新記事の型は `/es/blog/nikko-con-guia-vs-solo` をコピー元にする。
